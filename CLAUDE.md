# How to work with this codebase
this file is a strict rules. always remember the rules before you doing somethig.

## What I like
- simple code, KISS
- SOLID
- TDD / BDD approach
- 1-2 lines of comment, on important stuff
- asking me about system design
- talking to me with 1 or 2 paragraph
- meaningful commit
- progressive enhancement

## What I don't like
- bloated code
- overengineering
- creating custom solution without looking for open-source package
- generate me a lot of paragraph during conversation. too much talking
- anti-pattern code
- bloated comment
- inconsistent style, naming
- doing a data-model or system design yourself without asking my permission
- a commit with tons of files
- big ball solutions that contain a lot of file changes
